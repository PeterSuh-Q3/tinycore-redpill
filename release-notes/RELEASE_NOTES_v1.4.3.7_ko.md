# alpine-redpill v1.4.3.7

## 🔀 고정 IP가 이제 최대 8개 NIC을 지원하며, 기본 게이트웨이는 하나만 소유합니다

예전엔 고정 IP 메뉴가 NIC 1개만 설정할 수 있었습니다. 이제는 목록형 메뉴로 바뀌어 최대 8개(로더 cmdline의 `mac1`~`mac8` 상한과 동일)까지 각각 독립적으로 추가할 수 있고, 설정하지 않은 포트는 목록에 아예 나타나지 않고 그냥 DHCP로 남습니다.

- 🧩 `user_config.json`의 `ipsettings`가 단일 NIC용 flat object에서, 설정된 NIC마다 하나씩 들어가는 배열로 바뀌었습니다. 기존 단일 NIC 설정은 메뉴(또는 로더)가 파일을 처음 건드리는 순간 자동으로 마이그레이션됩니다.
- 🚦 배열 중 정확히 하나만 `primary`로 지정되어 기본 게이트웨이를 소유하므로, 여러 NIC이 `ip route add default`를 두고 서로 경쟁하지 않습니다. primary가 아닌 NIC은 게이트웨이를 비워둘 수 있는데, 이는 그 NIC이 primary와 같은 서브넷일 때만 정상 동작하며, 그렇지 않으면 그 NIC은 자신의 로컬 서브넷 안에서만 통신할 수 있습니다.
- ⬆️ NIC을 primary로 승격시킬 때(직접 게이트웨이를 입력하거나, 전용 "주 게이트웨이로 지정" 액션을 통해) 승격되는 NIC 자신의 게이트웨이 필드가 비어있으면 이전 primary의 게이트웨이를 자동으로 물려받아, 승격 과정에서 기본 라우트가 조용히 사라지는 일이 없습니다.

## 🌐 DNS가 NIC별 필드에서 전역 설정 하나로 바뀌었습니다

Linux의 `resolv.conf`는 인터페이스 개념이 없어서, non-primary NIC에 입력한 DNS 값이 애초에 그 NIC 전용으로 격리된 적이 없었습니다.

- DNS는 이제 `user_config.json` 최상위의 `netdns.ipdns` 값 하나로 통합되어, NIC 개수와 무관하게 한 번만 적용되며, 고정 IP 메뉴에서 HTTP Proxy 바로 위에 위치합니다.
- NIC이 1개라도 고정 IP로 설정되면 필수값이 되어, 값을 설정하기 전까지는 고정 IP 메뉴를 빠져나갈 수 없고 안내 메시지가 표시됩니다.
- `netproxy`/`netdns`는 이제 값을 한 번도 저장한 적 없어도 `user_config.json`에 항상 빈 스캐폴드로 나타납니다 - 예전엔 값을 처음 저장하기 전까지 키 자체가 아예 없었습니다.

## 📋 메뉴 위치 재배치

고정 IP 설정이 추가기능 하위메뉴에서 빠져나와 메인 메뉴로 이동했고, 추가기능 항목 바로 위에 위치합니다. 대신 TCB/FKC 자동 업데이트 관리와 이전 버전 재빌드는 메인 메뉴에서 추가기능 하위메뉴 안으로 이동했습니다.

## ⚡ 고정 IP가 메뉴를 나가는 즉시 적용됩니다

고정 IP를 저장하고 완료로 나가는 순간, 오프라인 첫 부팅 설정 경로와 동일한 즉시 적용 로직이 호출되어 실행 중인 FRIEND 커널에 바로 반영됩니다 - 다음 부팅까지 기다릴 필요가 없습니다.

이번 릴리즈는 멀티 NIC 고정 IP 작업 중 로더 쪽 절반을 마무리한 것이며, 짝이 되는 tcrpfriend(부팅 시 cmdline 빌더, 콘솔 IP 표시)와 misc addon(`mshell-network.service` 오탐 실패 수정) 변경 사항은 각자의 저장소에서 별도로 배포됩니다.
