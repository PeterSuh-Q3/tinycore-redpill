# alpine-redpill v1.4.3.3

## 💽 "Syno 디스크에 부트로더 주입" 기능을 처음부터 끝까지 다시 고쳤습니다 (2TB 초과 GPT 디스크 포함)

이 메뉴 기능은 별도 USB/SATA 로더 없이도, 시놀로지 데이터 디스크의 SHR/GPT 여유 공간에 직접 FRIEND 커널 부팅 항목을 만들어 줍니다. 실기에서만 드러나는 버그가 여러 개 쌓여 있었는데, 이번에 실기에서 반복 테스트하며 전부 찾아 고쳤고, 2TB가 넘는 GPT 디스크에서도 처음부터 끝까지 에러 없이 완료되는 것까지 확인했습니다.

- 🔧 **2TB 초과(GPT) 디스크 주입이 이제 정상 동작합니다.** TinyCore 시절 남아있던 `/usr/local/sbin/gdisk` 하드코딩 경로 때문에 Alpine에서는 `sudo`가 아예 실패하고 있었습니다(실제로는 `/usr/bin/gdisk`에 설치됨). 또한 `tce-load` 호환 셈(shim)이 `gptfdisk`만 설치하고, `remove_loader()`가 실제로 필요로 하는 `sgdisk` 패키지는 따로 설치하지 않고 있었습니다 — 둘 다 수정했습니다.
- 🧭 **새 파티션이 이제 올바른 여유 공간에 만들어집니다.** 최신 `fdisk`(util-linux 2.42.1 이상)에서는 기존의 고정 섹터 오프셋 계산이 거부당하는 경우("Sector X is already allocated")가 있었고, 이게 스크립트의 자동 응답 흐름을 어긋나게 만들어 결국 엉뚱한(너무 작은) 여유 공간으로 조용히 떨어지는 문제가 있었습니다. 이제 섹터 계산을 동적으로 하도록 고쳤고, "기존 파일시스템 서명을 지울까요?"라는 대화형 확인 프롬프트도 더 이상 자동화 흐름을 어긋나게 하지 않습니다.
- 🩹 **실기에서만 재현되던 여러 크래시를 고쳤습니다**: 파티션 경계 계산에서 `sudo` 누락, 아직 조립된 상태인 md/LVM 스택 때문에 `blockdev --rereadpt`가 "Resource busy"로 실패하던 문제(이제 자동으로 중지 후 재시도), 작은 파티션에서 `mkfs.vfat -F16`이 조용히 실패하던 문제, `remove_loader()`가 마운트를 정리하지 않고 남겨두던 문제, 이 기능을 단독 실행할 때 발생하던 변수 미정의 크래시.
- 🧹 **어차피 실패할 단계를 제거했습니다**: 예전의 `xtcrp.tgz` 다운로드와 grub 항목은 애초에 여유 공간에 들어갈 수 없었기 때문에, 주입 과정에서 완전히 제거했습니다.
- 📊 **용량 표시가 더 명확해졌습니다**: 4번 파티션에도 FRIEND 커널 파일별 용량 상세 내역이 표시되며(7번 파티션과 동일한 방식), 7번 파티션의 "사용량" 로그도 더 이상 로더 파티션 전체 사용량을 전송 용량인 것처럼 잘못 보여주지 않습니다.
- 🖱️ 디스크 선택과 확인 프롬프트가 이제 일반 텍스트 대신 dialog UI로 표시됩니다.

## 📦 MSHELL Manager와 Syno Smart Info가 이제 스스로 최신 버전을 받아옵니다

두 애드온 패키지 모두 이제 AMD GPU 런타임 애드온과 동일한 방식으로, 빌드 시점에 각자의 공개 GitHub 릴리즈에서 최신 버전을 직접 가져옵니다. 예전처럼 이 저장소에 버전이 고정된 사본을 매번 손으로 다시 커밋해 둘 필요가 없어졌습니다. 사용자 입장에서 달라지는 건 없고, 두 패키지 모두 새 버전이 나오면 지연 없이 다음 로더 빌드부터 바로 반영됩니다.

## 🧹 그 외 자잘한 수정

- `firmwareamdgpu.tgz`(DSM 램디스크의 약 28%)는 이제 빌드 머신에서 실제로 AMD GPU가 감지될 때만 포함됩니다(예전엔 무조건 포함).
- 기본 SATA 포트 매핑에서 쓰이던 하드웨어 제외 목록이 실제로 지원해야 할 플랫폼 목록과 어긋나 있던 문제를 고쳤습니다(epyc7002/epyc7003/epyc7003ntb/icelaked가 빠져 있었습니다).

위의 디스크 주입 관련 수정 사항은 모두 실기에서 처음부터 끝까지 검증했으며, 에러 없이 완료되는 전체 주입 과정까지 확인했습니다.
