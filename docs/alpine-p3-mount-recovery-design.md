# Alpine 로더 P3 마운트 보정 설계

## 목적과 확인된 현상

`user_config.json`과 빌드 산출물을 담는 로더 3번 파티션(P3)을 `tc` 계정이 안정적으로 읽고 쓸 수 있게 한다. DoH 초기 검증과 기존 `functions.sh` 소싱 시 검증은 유지하되, 실패한 재마운트가 중복 마운트를 남기지 않도록 한다.

2026-10-04 실기 192.168.45.27에서 확인한 상태:

- `/home/tc/functions.sh` SHA-256은 당시 로컬 최신본과 일치한다.
- `/dev/nvme0n1p3`은 `/media/nvme0n1p3`에 한 번, `/mnt/nvme0n1p3`에 두 번 마운트되어 있었다. 세 항목 모두 `ro,fmask=0022,dmask=0022`였다.
- `/mnt/tcrp` 링크는 없었고 `/home/tc/user_config.json`은 P3 링크가 아닌 일반 파일이었다.
- 블록 장치의 읽기 전용 플래그는 0이었다. `fsck.vfat -n`은 dirty bit를 보고했지만 파일시스템은 변경하지 않았다. 로그에서 P3의 I/O 오류나 커널의 `errors=remount-ro` 발동은 확인되지 않았다. 따라서 **dirty bit가 `ro`의 원인이라고 확정하지 않는다.**
- 현재 `ensure_loader_partition_mounted()`는 마운트 옵션이 잘못되면 `/mnt` 마운트를 한 번만 해제한 뒤 다시 마운트한다. 동일 장치의 다른 마운트와 중첩 마운트를 검사하지 않는다. 실패 후 `sudo mount "${dev}"` 재시도는 새 마운트를 더할 수 있다.

## 책임 분리

1. **부팅 초기(overlay 로드 이후, SX와 `menu.sh` 시작 전)**: P3 UUID `6234-C863`의 실제 장치와 모든 마운트를 식별하고, 가능한 경우 단일한 쓰기 가능 마운트를 준비한다. `rebuildfstab`의 `umask=000` 항목 생성만으로 이미 존재하는 마운트 옵션이 바뀌지는 않는다. 초기 보정 호출 위치는 `restore-packages.start`에서 `rebuildfstab` 직후, `setup-disk-swap` 직전으로 한다. 다만 initramfs의 `/media/<device>` 마운트가 이 시점에 계속 필요한지와 해제 가능 여부를 실기에서 먼저 검증한다.
2. **`functions.sh`/`functions_t.sh`**: 기존 검증 호출은 유지한다. 정상 상태에는 무변경으로 통과하고, 잘못된 상태에는 장치별 전체 마운트 상태를 검사한 뒤 안전한 범위에서만 복구한다. `menu.sh`의 DoH 사전검증은 마운트를 수정하지 않는다.
3. **파일시스템 오류**: 커널 I/O 오류, 실제 `errors=remount-ro` 발동, 블록 장치 읽기 전용 상태가 확인되면 자동 강제 `rw` 또는 자동 `fsck`를 하지 않는다. 명확한 오류와 진단 명령을 출력하고 빌드/설정 저장을 중단한다.

구현 위치: `alpine/ensure-loader-p3`를 영속화 파일의 `/usr/local/sbin/ensure-loader-p3`로 설치한다. `alpine/local.d-restore-packages.start`는 이를 `rebuildfstab` 다음, `setup-disk-swap` 이전에 호출한다. `functions.sh`와 `functions_t.sh`는 파일이 있을 때 같은 스크립트를 호출한다. 구형 영속화 파일에서 스크립트가 없고 P3가 중복 마운트되어 있으면 기존 복구 루틴으로 진입하지 않고 실패한다.

## 보정 알고리즘

1. UUID로 P3 장치를 식별하고 `/dev/<name>`과 `/mnt/<name>`을 확정한다. 장치명 문자열만으로 다른 파티션을 추정하지 않는다.
2. `/proc/self/mountinfo` 또는 `findmnt`로 **해당 장치의 모든 마운트 ID·마운트포인트·옵션**을 수집한다. `mountpoint -q`와 `findmnt --target` 한 번만으로 중복 여부를 판단하지 않는다. `/media`와 `/mnt`를 모두 포함한다.
3. 정상 조건은 `/mnt/<name>`의 단일 마운트가 `rw,fmask=0000,dmask=0000`이고, `tc`가 P3의 기존 설정 파일과 디렉터리에 쓸 수 있는 것이다. `/media`의 추가 마운트가 허용되는지 여부는 초기 마운트 소유권 확인 후 확정한다. 허용하더라도 동일 장치의 모든 마운트에서 `ro`/`rw` 상태가 모순되지 않아야 한다.
4. 복구가 필요한 경우 먼저 사용 중인 P3 스왑파일, 열린 파일, 작업 디렉터리와 중첩 마운트를 확인한다. 사용 중이면 언마운트하지 않고 실패한다. 특히 `setup-disk-swap`보다 앞에서 보정해 활성 스왑과 충돌하지 않게 한다.
5. 안전하게 해제 가능한 마운트만 **마운트 ID/역순**으로 처리한다. 한 번의 `umount` 성공을 전체 해제로 간주하지 않는다. 기존 `/media` 마운트가 initramfs 또는 패키지 복원에 필요한 경우에는 유지 가능한 다른 방식을 검증하기 전까지 해제하지 않는다.
6. 이전 마운트가 남아 있는 상태에서 동일 장치를 무조건 다시 `mount`하지 않는다. 단일 `/mnt/<name>` 마운트를 `vfat,rw,umask=000`으로 만든 뒤 전체 마운트 목록과 실제 `tc` 쓰기 가능 여부를 재검증한다. 실패 시 추가 마운트를 만들지 않고 명시적으로 오류를 반환한다.
7. 검증 성공 후에만 `/mnt/tcrp` 링크와 `/home/tc/user_config.json` 링크를 확인·정비한다. 다른 실제 파일이나 잘못된 링크를 조용히 덮어쓰지 않는다.

## 실패 처리와 진단

- 오류 메시지에 장치, 모든 마운트포인트·옵션, 실패 단계, `errno`에 해당하는 명령 오류를 남긴다. 비밀번호나 `user_config.json` 내용은 기록하지 않는다.
- `functions.sh` 소싱 시 보정 실패를 단순 경고로 흘려보내지 않도록, P3 쓰기가 필요한 경로의 시작점에서 실패 코드를 확인한다. DoH 팝업은 이미 구현된 독립 검증을 유지한다.
- 읽기 전용 원인을 확인하기 위한 진단은 `blockdev --getro`, `/proc/self/mountinfo`, P3 관련 `dmesg`, `fsck.vfat -n`으로 제한한다. 실제 복구용 `fsck`는 언마운트된 장치에 대해 사용자가 별도로 결정한다.

## 검증 시나리오

1. 정상 단일 `rw,0000` 마운트: 재마운트 없이 통과하고 기존 링크가 유지된다.
2. 단일 `rw,0022` 마운트: 안전한 재마운트 후 `tc` 쓰기 시험까지 통과한다.
3. 단일 `ro,0022` 마운트: 원인이 단순 초기 마운트인지 확인한 경우에만 복구한다. 복구 불가 시 중복 마운트 없이 실패한다.
4. `/media` 1개와 `/mnt` 2개가 있는 45.27 재현 상태: 전체 목록을 감지하고, 안전한 해제 조건이 충족되지 않으면 **추가 마운트 없이** 실패한다.
5. P3 스왑파일 활성화·열린 파일·커널 I/O 오류: 자동 해제/강제 복구를 하지 않고 실패한다.
6. P3 장치 없음·UUID 불일치·잘못된 `/mnt/tcrp` 링크: 다른 파티션에 쓰지 않는다.
7. 부팅 후 `menu.sh` DoH 초기 읽기, DoH 전환 저장, 일반 빌드, 백업 및 재부팅: 모두 같은 P3을 사용하고 중복 마운트가 다시 생기지 않는다.

45.27의 현재 실행 세션은 수정하지 않았다. 새 영속화 파일로 부팅할 때도 `/media` 초기 마운트를 해제할 수 있는지, 재마운트가 실제로 `rw,0000`이 되는지 확인해야 한다. 사용 중인 마운트가 해제되지 않으면 강제 해제하지 않고 오류를 반환한다. 파일시스템 자동 수정은 하지 않는다.
