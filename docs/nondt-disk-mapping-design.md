# Non-DT 디스크 매핑 도우미 설계

상태: 설계안. 구현 및 플랫폼별 실기 검증 전이다.

## 1. 목적과 범위

Non-DT 모델에서 SATA 컨트롤러, SAS/HBA, USB 로더와 데이터 디스크의
관계를 확인하고 `SataPortMap`과 `DiskIdxMap`의 후보를 검토·적용한다.
단순히 포트 수를 합산해 정확한 DSM 슬롯 번호가 보장된다고 주장하지 않는다.
장치 인식 누락과 기존 볼륨의 디스크 순서 변경 위험을 먼저 표시한다.

대상은 Non-DT 모델이다. DT 판정은 커널 버전만으로 추정하지 않고 실제
선택 모델의 매핑 방식과 기존 플랫폼 판정을 대조한다. 불명확한 모델은
자동 적용하지 않는다. 파티션 생성·포맷·RAID 조립·재구성은 범위 밖이다.

## 2. 기존 구현에서 확인한 사항

- `rploader.sh.deprecated`의 `satamap()`은 PCI SATA 컨트롤러와
  `/sys/class/ata_device`를 세고 누적 오프셋을 만든다. SAS/HBA는 출력만
  한다. SATABOOT, QEMU, VMware 30포트에는 휴리스틱이 들어 있다.
- `menu_m.sh`의 `showsata()`는 SATA 포트 연결·DUMMY 상태 및 SAS/HBA,
  USB, NVMe 수량을 표시하지만 현재 호출 메뉴가 없고, 설정값이나 각
  디스크의 최종 매핑 결과를 표시하지 않는다. 수집 로직은 참고하되 그대로
  정확한 매핑 결과로 사용하지 않는다.
- 기존 `remapsata()`에는 `hostN + 1`로 ATA 번호를 추정하는 부분이 있다.
  실제 sysfs 관계를 사용하는 새 수집기로 대체하기 전까지 정확성을 보장하지
  않는다. 기존 동작은 사용자 승인 없이 삭제하지 않는다.
- `prefillDefaultSataPortMap()`은 `maxdisks` 기반 단일 컨트롤러 기본값을
  넣으며, 메뉴의 `noconfig` 빌드 경로와 초기화 방지 옵션도 연관된다.
  새로 승인한 값이 이후 빌드에서 지워지거나 기본값으로 대체되지 않도록
  이 경로와 헤드리스 자동 재빌드 경로를 함께 검증해야 한다.
- Non-DT `disks` addon은 DSM 환경에서 디스크를 열거해 `maxdisks`,
  `usbportcfg`, `esataportcfg`, `internalportcfg`를 처리한다. 사용자
  지정값을 고려하며 설치 단계에서 DSM의 두 synoinfo 설정에 반영한다.

## 3. 설정 간 관계

| 설정 | 초기 구현 방침 |
| --- | --- |
| `SataPortMap`, `DiskIdxMap` | 한 쌍으로 후보 생성·검증·적용한다. |
| `sata_remap` | 별도 SATA 순서 조정 방식으로 표시한다. 자동 매핑과 동시 신규 적용은 기본 차단한다. |
| `SasIdxMap` | 별도 SAS/HBA 설정으로 현재 값을 표시하고 보존한다. 자동 계산·삭제하지 않는다. |
| `usbportcfg`, `esataportcfg`, `internalportcfg` | 현재 값과 가능한 충돌을 진단한다. 자동 생성·수정하지 않는다. |
| `maxdisks` | 인덱스 범위 검증에 사용한다. 임의 상향하지 않는다. |

위 네 매핑 파라미터가 커널 수준에서 모두 상호 배타적이라는 뜻은 아니다.
특히 SATA 한 쌍은 같이 쓰며 `SasIdxMap`도 공존 가능성을 유지한다.
`sata_remap`과의 조합 동작은 플랫폼·DSM·LKM별로 검증되지 않았으므로
초기 자동 적용 정책에서만 보수적으로 제한한다. 기존 혼용 설정은 스캔이나
메뉴 진입만으로 변경하지 않는다. 고급 혼용 지원은 실측 검증 후 별도 설계한다.

설정의 부재, 빈 값, `0`은 서로 다른 상태로 취급한다. `SasIdxMap`의 숫자
형식·적용 순서·지원 범위 및 SATA/HBA 간 영향은 정확한 커널/LKM 경로와
실기 결과가 확보되기 전까지 확정하지 않는다.

## 4. 메뉴 설계

기존 빌드 사전 옵션의 Non-DT `sata_remap` 진입점은 유지하되, 사용자에게
매핑 도우미 하위 메뉴를 제시한다. 기존 기능을 자동 삭제하지 않는다.

1. **현재 매핑 및 컨트롤러 확인**: 장치 토폴로지, 설정값 및 진단 표시.
2. **SATA 자동 매핑**: `SataPortMap`/`DiskIdxMap` 후보, 범위·경고 표시 후 적용.
3. **SATA 포트 순서 조정**: 기존 `sata_remap` 확인·편집. 기존 SATA 한 쌍과의 혼용 경고.
4. **SAS/HBA 설정**: HBA 장치와 `SasIdxMap`의 현값 확인. 초기에는 자동 수정 없음.
5. **변경 전 설정 복원**: 대상 설정과 명령줄을 검증한 백업에서 복원.

기존 `sata_remap`이 있을 때 자동 매핑 신규 적용은 충돌 해결 전 차단한다.
어떤 값을 제거할지 명시적으로 선택·확인하게 하며 취소 시 원본을 보존한다.
SATA 설정 선택이 `SasIdxMap` 또는 portcfg를 삭제하는 일은 없어야 한다.
적용 성공 시 로더 재빌드 필요성을 안내한다. 한글·영문 포함 기존 i18n
규칙을 따르며 `lang.tgz`는 지정된 워크플로로 생성한다.

## 5. 수집 및 제안

컨트롤러별 PCI 전체 주소와 장치 ID, 드라이버, sysfs 부모 경로, ATA 포트와
SCSI host 관계, DUMMY 여부, 연결·빈 포트를 수집한다. SAS/HBA는 드라이버와
H:C:T:L·디스크를 별도로 표시하며 멀티패스, 확장기, 비동기 탐지를 고려한다.
USB/SATA/NVMe 로더는 파티션 식별자와 실제 장치 경로로 식별하고 데이터
디스크와 구별한다. 가능하면 WWN·시리얼·모델을 사용하되 없거나 중복되면
불확실성을 표시한다. `/dev/sdX`, `hostN`, `ataN`은 현재 부팅의 관찰값이다.

로더와 DSM의 탐지 순서가 같다는 가정을 강제하지 않는다. PCI 정렬만으로
DSM 순서를 확정하지 않으며, 포트 멀티플라이어·가상 컨트롤러·부트 디스크
공유 컨트롤러·DUMMY 포트 등은 모델별 검증 전 수동 검토 또는 자동 적용
차단 대상으로 둔다. VMware 30포트를 무조건 8포트로 바꾸지 않는다.
10포트 이상 인코딩과 유효 범위는 대상 커널의 실제 파서를 확인하기 전에는
임의 확정하지 않는다. 가용 디스크 수가 실제 포트 수와 같다고 가정하지 않는다.

두 컨트롤러가 DSM에서도 같은 순서로 확인되고 각각 4·2개 포트를 사용하는
단순 사례의 계산 예시는 `SataPortMap=42`, `DiskIdxMap=0004`다. 이는
물리 베이 또는 DSM 최종 슬롯의 보증이 아니다. 후보의 인덱스 범위 중복,
누락, `maxdisks` 초과와 SATA/SAS/USB 분류 충돌은 명시적으로 검사한다.

## 6. 포트 분류와 addon 경계

`disks` addon이 DSM의 실제 장치 인덱스를 기준으로 분류하는 현행 역할을
존중한다. 도우미는 `synoinfo.conf`와 사용자 설정, 가능한 경우 addon의
결과를 나란히 보여주고 USB·eSATA·내부 비트 중복과 `maxdisks` 제한을
경고한다. 값의 의미나 적용 시점이 확인되지 않으면 `미확인`으로 보고한다.
특히 비연속 USB 인덱스와 높은 HBA 인덱스가 섞인 경우 범위형 마스크가
중간 디스크를 포함하는지 검증한다. 초기 릴리즈에서는 portcfg를 쓰지 않는다.

## 7. 저장·빌드·복구

- 원본 `user_config.json`과 대상 항목의 부재/값을 백업하고 변경 전후를 보여준다.
- SATA 두 값을 한 번의 검증된 JSON 갱신으로 함께 기록하고 기존 안전한
  설정 저장 및 `sync_usb_line()`을 활용한다. 심볼릭 링크를 덮어쓰지 않는다.
- USB/SATA 부트 명령줄과 실제 빌드 산출물의 최종 토큰을 비교해 중복,
  누락, 이전 값 잔존을 차단한다. `SasIdxMap`의 기존 수동값은 보존한다.
- 기존 `sata_remap`, 초기화 방지 옵션, `noconfig`, 일반/자동 재빌드에서
  의도한 값이 지속되는지 검증한다. 실패 시 이전 설정으로 복원한다.
- Docker 원격 빌드의 컨테이너 장치를 사용자 호스트 토폴로지로 취급하지
  않는다. 호스트에서 확인된 설정을 사용하고, 정보가 없으면 자동 탐지를
  중단하거나 명시적인 수동 검토로 전환한다.

## 8. 검증 및 완료 기준

1. 고정 sysfs/lspci fixture: SATA 1·다중 컨트롤러, 빈 포트, DUMMY,
   10포트 이상, QEMU·VMware, SATABOOT 공유, 누락·중복 식별자.
2. 혼합 장치 fixture: SATA+LSI HBA, 다중 HBA, USB 중간 인덱스, 확장기,
   탐지 지연. 미지원 사례는 잘못된 후보 대신 경고·적용 차단을 확인한다.
3. 기존 사용자 설정·부재·빈 값·중복 명령줄, `sata_remap` 혼용,
   `SasIdxMap` 보존, portcfg 사용자 override, 롤백과 재빌드 지속성.
4. Non-DT 실기에서 로더와 주니어/DSM의 PCI·드라이버·디스크 WWN/시리얼,
   슬롯 번호, `synoinfo.conf`, SMART 및 재부팅 후 결과를 비교한다.
   디스크 추가·제거 및 초기화 지연도 검증한다.
5. 기존 볼륨을 가진 장비는 반드시 복구 가능한 백업과 사용자 확인 후
   시험한다. 매핑 변경이 RAID를 조립·초기화하는 행위로 이어지지 않게 한다.

SATA 전용에서 확실한 결과가 나오는 사례부터 제공한다. SAS 자동 인덱스,
다중 컨트롤러 순서 보장, portcfg 자동 보정 및 장치 종류별 호환성은 별도
실증 전까지 미완료로 표시한다.
